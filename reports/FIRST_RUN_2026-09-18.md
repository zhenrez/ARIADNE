## 2. First-run runtime findings

### 2.1 Launcher

The Windows one-click launcher successfully established the intended bootstrap path:

- official 64-bit CPython 3.13 preferred, 3.11 accepted;
- unrelated Conda / Anaconda / NVIDIA / CUDA / other venv interpreters rejected;
- local `.venv` created or replaced;
- inherited Python/Conda/NVIDIA/CUDA variables isolated inside launcher process;
- project requirements step executed;
- SQLite feature and writer-lock checks;
- source compilation and regression suite;
- ledger verification;
- available localhost port discovery;
- Warden/server startup;
- browser launch.

### 2.2 Missing operator controls

The first run exposed a major usability/control gap in the browser UI:

- no Pause Warden control;
- no Resume control;
- no Stop ARIADNE control;
- no Pause Downloads control;
- no acquisition queue cancel/skip control;
- no source-management interface;
- no storage budget or free-space guard visible to the operator;
- no source pin/evict controls;
- no backup/snapshot retention controls;
- closing the browser does not stop the Warden.

This is a release-blocking usability gap for unattended operation.

### 2.3 Storage behavior

The first run exposed an unacceptable local-storage amplification path.

For a fetched source, the current implementation can retain:

1. downloaded file under `inbox/acquired`;
2. copied canonical original under `custody/SRC-...`;
3. full extracted text in SQLite `source_profiles.text`;
4. extracted lines again in `passages`;
5. FTS5 index representation;
6. gram/search indexes and graph/findings/history;
7. append-only state-history row copies;
8. complete SQLite snapshots after research cycles;
9. pre-launch database backups over time.

This is not suitable for a machine with limited free disk space.

### 2.4 Snapshot amplification

The Warden currently creates a complete SQLite snapshot after P0-blocked cycles and after ordinary research cycles. As the database grows, repeated full snapshots can dominate disk use.

### 2.5 Custody duplication

Web acquisition currently writes a fetched object to `inbox/acquired` and then `register_source()` copies it into canonical custody. The staging copy is not automatically removed after successful custody registration.

### 2.6 Chat/runtime bridge

The local Warden can receive messages through `/api/messages`, but this ChatGPT conversation is not automatically connected to the localhost runtime. Therefore browser-chat research and local Warden research are still separate processes unless an explicit bridge is established.
